# IEEE ClimateChain × NaFT Core — 6-paper research bridge (2026-11-08)

## Purpose

The IEEE edition independently experiments with **raw-gasflux data**, **audit evidence**, and a **read-only chain verifier**. The primary public [NaFT Core](https://github.com/Takzin1/NaFT) also implements evidence provenance, an OPM/FAIR research sidecar, a per-Claim research cache, and a Blue Carbon intake adapter. Do not fork the engines or silently assume the different MRV domains have identical measurement rules.

Instead, this edition provides a **pinned-source, offline, research-only receipt validator**:

- Core commit: `9d1b316b9599945fcd9c135d695b4f8899be7c62`
- CLI: `scripts/ieee-core-receipt-intake.mjs`
- Original code is independently authored in IEEE; the cross-repository job checks out the exact public Core version.
- Test harness: `tests/ieee-core-receipt-intake.test.mjs` and the [cross-repository workflow](../.github/workflows/ieee-core-research-bridge.yml).

### Reproduce (Node.js 24)

From the Core checkout (after loading its five compiler JS files), generate an actual synthetic research receipt:

    const input = syntheticClaim('IEEE-CORE-RESEARCH-ONLY');
    const pack = COMPILER_REGISTRY['NAFT-SYNTHETIC@1'];
    const pkg = compileEvidence(input, pack);
    const receipt = naftResearchInteropReceipt(pkg, input, pack);

Write this research-only receipt to a local JSON file; do NOT commit real field evidence. From the IEEE checkout:

    node scripts/ieee-core-receipt-intake.mjs /path/to/core-interop.json > ieee-core-receipt.json
    node --test tests/ieee-core-receipt-intake.test.mjs

The cross-repo workflow performs both steps and independently checks the Core graph digest using IEEE's own SHA-256 canonicalizer.

## Paper-derived rationale — six distinct works, seven uploaded files

The two uploaded “Incremental Computation with Names” PDFs are byte-identical and count as one work. Original uploaded PDF bytes are **not published** in this public repository. The [machine-readable source registry](../research/ieee-core-theory-2026-11-08/source-and-work-queue.json) holds DOI, local-file SHA-256 and research-only scope; it does not authenticate publisher originals or confer redistribution rights.

| Priority | Paper | Application and caveat |
|---|---|---|
| P0 | Hammer et al. (2015), *Incremental Computation with Names* | Give dynamic computation nodes stable names, then test from-scratch agreement; this theorem does not automatically apply to NaFT. |
| P0 | Mokhov, Mitchell & Peyton Jones (2018), *Build Systems à la Carte* | Explicitly separate task ordering and change/rebuild policies; make performance measured rather than assumed. |
| P1 | Green, Karvounarakis & Tannen (2007), *Provenance Semirings* | Represent alternative and joint evidence derivations for **why/how** explanations. Polynomial addition here does not mean adding tonnes of CO₂e. |
| P1 | Krafczyk et al. (2021), *Reproduction Package* | Archive exact code+data+parameters+environment for third-party computational reproduction, not independent scientific validation. |
| P1 | Batjes et al. (2024), multi-ecosystem MRV framework | Make measurement pools, spatial coverage, uncertainty and human validation domain-specific across agriculture and Blue Carbon. |
| P2 | Körner et al. (2025), digital MRV for decarbonization | Treat measuring, reporting and verifying as distinct responsibilities; never upgrade data receipt to an authorized carbon credit. |

## What is actually checked

The importer accepts only Core's `naft-research-interop-receipt-1` envelope, recomputes the OPM crosswalk digest, checks graph direction, typed edges/roles and cycles, verifies FAIR 15-item metadata coverage, links the package SHA-256 to OPM and FAIR source metadata, and rejects any institutional or blockchain upgrade. It emits a reduced `naft-ieee-core-research-bridge-1` receipt.

Crucially, the importer **cannot verify that the source package was honestly generated by the original Core**, whether evidence reflects real observations, whether an OPM graph represents complete causality, or whether any institutional method is satisfied. Public hash consistency is not a digital signature; independent custody and signed provenance remain future work.

Neither the adapter nor the workflow submits Sepolia transactions or issues carbon credits. The pre-existing read-only Sepolia verifier remains separate.
